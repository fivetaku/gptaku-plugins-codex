# 예제: 인플루언서 후보 선별

> 골라제브 0.1.0이 실제로 낸 설계안입니다(아이디어 모드 → 설계 모드). 생성 조건: 2026-11-13, 원본 플러그인(golla-jev)만 불러온 헤드리스 에이전트 세션에 아래 요청 한 단락을 넣었습니다. 사람이 고친 것은 내부 경로 표기를 `$PLUGIN_ROOT`로 바꾸고(Codex판은 `$PLUGIN_ROOT`), 대화형 안내 한두 줄을 뺀 것뿐입니다. 업무 내용과 숫자 예시는 가상입니다. Jev API는 호출하지 않았습니다.

**넣은 요청**

> /golla-jev 우리 회사는 인플루언서 마케팅 대행사예요. 브랜드가 캠페인을 맡기면 마케터가 후보 인플루언서 200~300명의 프로필 소개, 최근 게시물 캡션 20개, 팔로워 수, 평균 좋아요를 보고 브랜드와 맞는 사람을 골라 제안서를 만듭니다. 이 업무에 제브 쓸 데가 있나요? 먼저 후보를 뽑아 주고, 가장 좋은 하나를 끝까지 설계해 주세요.

**점검 결과** (공개 전 점검표)

- 아이디어 모드 후보 5개 표 + 1순위 설계 8개 섹션 모두 있음
- 팔로워 파싱·참여율·개수 세기·협찬 태그 사전은 코드, "브랜드와 맞나"를 한 질문에 묻지 않고 신호를 코드가 합산
- 수치는 evidence에 있는 것만(Jack & Jill, 피싱 62.6%→95.0%, GC AI 96%→72%·88%, 묶음 97.1%)
- 질문 JSON 2블록 파싱됨. Score criteria가 낮은 단계→높은 단계 배열이라 공식 형식과 맞음

# 인플루언서 캠페인 후보 선별에 Jev 붙이기

결론부터 말씀드리면 쓸 데가 있습니다. 1순위는 **후보 200~300명을 브랜드 적합 신호로 1차 정렬하는 일**입니다. 캠페인 한 건에 캡션 4,000~6,000개를 "이건 관련 글인가, 협찬인가, 위험한가"로 하나씩 고르는 일이라 건수가 많습니다. 결과는 마케터가 제안서에 넣기 전에 다시 보므로, 틀려도 되돌리기 쉽습니다.

가정: 마케터는 브랜드 브리프(카테고리·타깃·톤·경쟁사)를 정해진 양식으로 받습니다. 후보 데이터는 이미 수집돼 글(JSON·시트)로 있습니다. 제안서 본문 디자인은 지금처럼 마케터가 합니다.

## 1부 — 후보 (아이디어 모드)

| 후보 | 무엇을 고르나 | 질문 타입 | 캠페인당 건수 | 틀리면 되돌리기 |
|---|---|---|---|---|
| ① 후보 1차 정렬 (권장) | 캡션마다 브랜드 관련·협찬·위험 여부, 사람마다 주 분야·톤 | Noul + Choice + Score, 코드가 합산 | 약 250명 × 60여 질문 | 쉬움(마케터가 상위권을 검토) |
| ② 표시 없는 협찬 비율 | `#광고` 같은 표시가 없는 글이 협찬인가 | Noul | 캡션 수천 개 | 쉬움 |
| ③ 브랜드 안전 검사 | 비방·논란·과장 효능 같은 위험 글이 있나 | Noul, 오류가 나면 사람에게 | 캡션 수천 개 | 보통(놓치면 사고가 남) |
| ④ 경쟁사 홍보 이력 | 경쟁사 이름이 나온 글이 홍보인가, 단순 언급인가 | 이름 대조는 코드, 홍보 여부는 Noul | 사전에 걸린 글만 | 쉬움 |
| ⑤ 인플루언서 DB 분야 태깅 | 캠페인과 무관하게 분야·톤 태그 달기 | Choice | 등록할 때 1회 | 쉬움 |

②~④는 ①의 신호로 그대로 들어가므로 ①로 묶어 설계합니다. 제안서 문장 쓰기는 Jev가 할 일이 아닙니다. Jev가 낸 값을 코드 템플릿이 문장으로 바꾸고, 다듬는 일은 사람이나 LLM이 맡습니다.

## 2부 — 인플루언서 후보 1차 정렬: Jev 워크플로 제안

가정: 캠페인당 후보 250명, 사람마다 캡션 20개. 제안서에는 상위 30명을 올리고 마케터가 그중에서 최종 확정합니다.

### 한눈에

후보 시트(소개·캡션·숫자) → 코드 전처리(숫자 파싱·태그·사전 대조) → 사람당 Jev 요청 1번(질문 60여 개) → 코드 합산·정렬 → 후보 대장 xlsx와 제안서 카드 초안

```
[후보 시트]      [코드 · 앞손]           [Jev · 스위치]             [코드 · 뒷손]             [산출물]
소개·캡션20·  →  팔로워 "3.2만" 파싱  →  사람당 1요청:           →  비율 집계·적합 점수  →  후보 대장 xlsx
팔로워·좋아요    참여율 계산             분야·톤·정보 깊이         위험 → 확인 필요        제안서 카드 초안
                 #광고·"내돈내산" 사전   캡션별 관련·협찬·위험     상위 30명 정렬          [사람] 최종 30명
                 경쟁사 이름 사전 대조   (items[i] 경로 지정)      템플릿 추천 문장
```

### 단계별

받아 적기 단계는 없습니다. 입력이 처음부터 글입니다.

| 단계 | 누가 | 하는 일 | 넘기는 것 |
|---|---|---|---|
| 입력 | 마케터 | 브리프 양식(카테고리·타깃·톤·경쟁사 목록)을 채우고 후보 시트를 올린다 | brief.json, candidates.csv |
| 전처리 | 코드 | 팔로워 문자열 파싱("3.2만", "12.3K"), 참여율(평균 좋아요 ÷ 팔로워), 예산 등급 구간 필터, 이상치(좋아요가 팔로워에 비해 지나치게 낮거나 높음) 표시 | 숫자 열 |
| 전처리 | 코드 | 캡션마다 `#광고 #협찬 #유료광고 #제품제공` 사전과 부정 표현 사전("광고 아님", "내돈내산", "협찬 아닙니다")을 대조하고, 경쟁사 이름 사전과도 대조한다 | 캡션별 태그 확정 여부, 질문을 낼지 말지 |
| 판정 | Jev | 사람당 요청 1번. 사람 단위 질문 3개, 캡션 단위 Noul 최대 3개 × 20개. 재료가 없는 질문은 코드가 미리 뺀다 | 확률·확실도 |
| 후처리 | 코드 | 관련 비율·협찬 비율·위험 건수를 집계해 적합 점수를 내고 정렬한다. 확실도가 낮거나 위험이 걸리면 '확인 필요'로 표시한다 | 순위표 |
| 산출 | 코드 | xlsx 후보 대장과 사람별 카드(템플릿 문장, 대표 캡션 원문 인용)를 만든다 | 파일 |
| 사람 확인 | 마케터 | 상위 40명과 '확인 필요' 전원을 보고 최종 30명을 고른다. 고친 내용은 다음 학습 표본으로 쌓는다 | 제안서 |

적합 점수의 가중치는 두 단계로 갑니다. 처음에는 마케터가 정한 가중치를 쓰고, 지난 캠페인의 채택·탈락 기록이 쌓이면 로지스틱 회귀로 맞춥니다. "브랜드와 맞나"를 Jev 질문 하나로 묻지 않습니다. 신호 여러 개를 코드가 합산하는 쪽이 낫습니다(아래 피싱 사례 근거).

### Jev 질문 초안

현재 모델은 `jev-1.14.0`(`jev-latest`)이고, 엔드포인트는 `POST https://api.typesafe.ai/v1/systemone`입니다. Choice·Score·Noul 형식은 2026-11-13에 docs.typesafe.ai에서 확인했습니다.

state 예시입니다. 숫자는 코드 몫이라 넣지 않았습니다.

```json
{
  "brand": {
    "category": "저자극 스킨케어",
    "target": "민감성 피부 고민이 있는 20~30대 여성",
    "tone": "차분하고 정보 위주"
  },
  "influencer": {
    "bio": "피부 얇은 사람의 순한 화장품 기록 🌿 성분 위주로 씁니다 | 협업 DM"
  },
  "items": [
    { "caption": "요즘 홍조 때문에 진정 크림만 세 개째 비교 중. 판테놀 함량 표로 정리해 봤어요 #내돈내산" },
    { "caption": "주말 캠핑 다녀옴 ⛺ 불멍 최고" },
    { "caption": "OO 브랜드에서 보내주신 세럼 2주 써 본 후기 #제품제공" }
  ]
}
```

questions 예시입니다. 캡션 질문은 `items[0]`만 보이고, 실제로는 `i`마다 같은 꼴로 만듭니다.

```json
{
  "category": {
    "type": "choice",
    "instructions": "`influencer.bio`와 `items`의 캡션 전체를 볼 때, 이 사람이 주로 다루는 분야는 무엇인가?",
    "criteria": {
      "뷰티·스킨케어": "화장품, 피부 관리, 메이크업을 주로 다룸",
      "육아": "아이 키우기, 육아용품을 주로 다룸",
      "패션": "옷, 코디, 잡화를 주로 다룸",
      "푸드": "음식, 맛집, 요리를 주로 다룸",
      "운동·건강": "운동, 식단, 건강 관리를 주로 다룸",
      "여행": "여행지, 숙소를 주로 다룸",
      "일상·기타": "한 분야로 묶이지 않는 일상 기록",
      "해당 없음": "캡션이 거의 없거나 분야를 판단할 내용이 없음"
    }
  },
  "tone": {
    "type": "choice",
    "instructions": "`items`의 캡션들이 주로 어떤 말투로 쓰였는가?",
    "criteria": {
      "차분·정보형": "사실과 비교, 성분, 사용 결과를 차분하게 전달",
      "감성·일상형": "분위기와 기분 중심의 짧은 기록",
      "유쾌·과장형": "농담, 감탄, 과장된 표현이 많음",
      "자극·논쟁형": "비꼬기, 공격적 표현, 논쟁 유도가 많음",
      "해당 없음": "말투를 판단할 만큼 글이 없음"
    }
  },
  "depth": {
    "type": "score",
    "instructions": "`items`의 캡션들이 `brand.category` 분야의 제품을 얼마나 구체적으로 다루는가?",
    "criteria": [
      "그 분야 제품 이야기가 거의 없다",
      "제품 이름이나 사진 언급 정도다",
      "사용감과 장단점을 적는다",
      "성분, 비교, 기간별 변화처럼 근거를 들어 자세히 적는다"
    ]
  },
  "rel_0": {
    "type": "noul",
    "instructions": "`items[0].caption`은 `brand.category`와 같은 분야의 제품이나 사용 경험을 다루는가?"
  },
  "spon_0": {
    "type": "noul",
    "instructions": "`items[0].caption`은 업체에서 제품이나 비용을 받고 올린 홍보 글로 보이는가? 제품 이름이 나오는 것만으로는 '예'가 아니다."
  },
  "risk_0": {
    "type": "noul",
    "instructions": "`items[0].caption`에 브랜드가 함께 보이기 꺼릴 내용(비방·혐오 표현, 논란 사건 언급, 과도한 음주·선정성, 질병을 고친다는 식의 효능 주장)이 있는가?"
  }
}
```

스크립트가 각 답을 쓰는 곳은 다음과 같습니다.

- `category`: 브리프 카테고리 보기의 확률을 적합 점수에 넣습니다. 확실도가 낮으면 '확인 필요'로 표시합니다.
- `tone`: 브리프 톤 보기의 확률을 점수에 넣습니다. '자극·논쟁형'이 우세하면 감점하고 확인 필요로 보냅니다.
- `depth`: 점수(0~3)를 정규화해 가중치에 넣습니다. 정보형 협업 제안에서 비중을 키웁니다.
- `rel_i`: 20개 중 '예' 비율이 "관련 게시물 비율"이 됩니다.
- `spon_i`: 코드 사전으로 협찬 여부가 확정되지 않은 캡션에만 냅니다. 사전에서 확정된 값과 합쳐 "협찬 비율"을 냅니다. 협찬 비율이 너무 높으면 감점합니다.
- `risk_i`: 하나라도 문턱을 넘으면 순위와 상관없이 '확인 필요'로 보냅니다. 오류나 시간 초과도 같은 쪽(막는 쪽)으로 처리합니다.

경쟁사 질문은 경쟁사 이름 사전에 걸린 캡션에만 추가합니다. 질문 내용은 "`items[i].caption`은 경쟁 제품을 추천·홍보하는가, 단순 언급인가"이고 Noul로 묻습니다.

### 산출물 모양

후보 대장 xlsx 미리보기입니다. 칸 이름 뒤의 기호는 출처입니다: [J] Jev 값, [C] 코드 계산, [원] 원문, [사람] 사람 몫.

| 순위[C] | 계정[원] | 팔로워[C] | 참여율[C] | 주 분야[J] | 톤[J] | 관련 글[J→C] | 협찬 비율[C] | 위험[J] | 적합 점수[C] | 상태[C] | 최종[사람] |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | @sample_01 | 32,000 | 4.1% | 뷰티·스킨케어 (0.97) | 차분·정보형 (0.91) | 14/20 | 3/20 | 0 | 0.86 | 자동 | ☐ |
| 2 | @sample_07 | 18,500 | 5.6% | 뷰티·스킨케어 (0.88) | 감성·일상형 (0.62) | 9/20 | 2/20 | 0 | 0.74 | 확인 필요(톤 확실도) | ☐ |
| … | @sample_42 | 120,000 | 0.6% | 일상·기타 (0.71) | 유쾌·과장형 (0.80) | 4/20 | 11/20 | 1 | 0.31 | 확인 필요(위험 1건) | ☐ |

제안서 카드 초안입니다. 문장은 코드 템플릿이 만들고, 같은 판정이면 같은 문장이 나옵니다.

> **@sample_01** · 팔로워 3.2만[C] · 참여율 4.1%[C]
> 최근 게시물 20개 중 14개가 저자극 스킨케어 관련[J→C]이고, 말투는 차분·정보형[J]으로 브랜드 톤과 맞습니다. 협찬 글 비율은 15%[C]입니다.
> 대표 게시물: "요즘 홍조 때문에 진정 크림만 세 개째 비교 중. 판테놀 함량 표로 정리해 봤어요"[원]
> 마케터 메모: ____________[사람]

### 닮은 사례

- **Jack & Jill 채용 선별**: 후보 더미에서 맞는 사람을 거르는 같은 꼴입니다. 1,000명당 비용이 $0.755에서 $0.092로, 처리 시간이 20.3초에서 10.3초로 줄었고, 10일 만에 운영에 들어갔습니다(저자 보고, typesafe.ai 블로그).
- **피싱 판정 신호 합산**: 최종 판정을 Jev 하나에 물으면 62.6%였고, 신호 질문 5개를 회귀로 합산하면 95.0%였습니다(저자 보고, awesome-jev-study `454`). "브랜드와 맞나"를 한 질문으로 묻지 않고 신호로 쪼개는 근거입니다.
- **배열 묶음 경로 지정**: GC AI 해커톤에서 배열을 경로 없이 한 질문으로 물었더니 96%가 72%로 떨어졌습니다(경로를 지정하면 88%, 저자 보고). 작성자 벤치에서는 `items[i]` 경로를 지정해 6건을 묶었을 때 97.1%(132/136)로 단건과 같았습니다(작성자 벤치 2026-11-13, jev-1.14.0).

### 조심할 곳

- **부정어와 해시태그**: "광고 아님", "내돈내산", "협찬 아닙니다"를 Jev가 거꾸로 읽을 수 있습니다. 작성자 벤치에서 "무알콜 맥주"를 술로 본 오답이 확실도 0.62~0.77로 나와 문턱만으로는 덜 걸렸습니다. 태그와 부정 표현은 코드 사전이 먼저 확정하고, 걸리지 않은 캡션만 Jev에 묻습니다.
- **숫자를 Jev에 맡기기**: 팔로워 비교, 참여율, "1.2만" 해석은 코드 몫입니다. 공식 약점 목록에 숫자 세기·비교가 있습니다. state에도 숫자를 넣지 않습니다.
- **캡션 20개를 한 질문으로 묻기**: "이 중 관련 글이 몇 개냐"는 세기 문제이고 배열 문제라 이중으로 약합니다. 캡션마다 `items[i]` 질문 하나를 두고 개수는 코드가 셉니다.
- **보기 이름 번역**: 브리프 단어("저자극 스킨케어", "차분·정보형")를 보기 이름에 그대로 씁니다. 작성자 벤치에서 영어 질문이 잃은 문항은 주로 보기 이름 번역 때문이었습니다(한국어 96.3%, 영어 93.5%).

### 시험 계획

- **표본**: 지난 캠페인 2~3건에서 두 층으로 만듭니다.
  - 신호 정확도: 후보 15~20명의 캡션 300~400개에 관련·협찬·위험 정답을 붙이고, 후보 80명에게 분야·톤 정답을 붙입니다. "광고 아님"·"내돈내산" 같은 어려운 캡션을 2~3할 섞습니다.
  - 순위 품질: 그 캠페인 후보 전원과, 마케터가 실제로 제안서에 넣은 명단을 씁니다.
- **정답**: 실행 전에 마케터 2명이 붙이고 해시로 잠급니다. 둘의 답이 갈린 건은 따로 표시합니다.
- **문턱**: id 해시로 dev 4할, holdout 6할을 나눕니다. dev에서 "자동 처리 중 오답 0"인 가장 낮은 확실도 문턱을 질문마다 고르고, holdout에서 자동 처리율을 확인합니다. 남의 문턱(0.7 등)은 쓰지 않습니다. 모델이 바뀌면 다시 고릅니다(작성자 벤치에서도 0.85에서 0.70으로 바뀌었습니다).
- **성공 기준**:
  - 신호 질문: holdout 자동 처리 중 오답 0~1건, 자동 처리율 80% 이상. 스킬의 '되돌리기 쉬운 일' 기준입니다.
  - 순위: 마케터가 실제로 고른 명단이 상위 40명 안에 얼마나 들어오는지(recall@40) 봅니다. 목표 수치는 첫 측정 뒤에 정합니다.
  - 위험 질문: 놓친 위험 0건을 따로 봅니다.
- **템플릿**: `$PLUGIN_ROOT/skills/golla-jev/bench/`를 작업 폴더로 복사해 `build_items.py`의 `WF`만 바꿉니다. 순서는 `run.py`(키는 `TYPESAFE_API_KEY` 환경변수로 주입) → `analyze.py` → `sweep.py`입니다.

참고로 `jev-1.14.0`은 공식 문서상 이미지 입력도 받습니다. 피드 이미지를 직접 넣는 것은 한국어 실측이 없으니, 1단계는 캡션 글로만 갑니다.

### 첫 걸음

반나절 분량입니다. 지난 캠페인 하나에서 후보 30명의 캡션 600개를 뽑아 코드 사전(협찬 태그·부정 표현)부터 돌립니다. 남은 캡션에 `rel_i`·`spon_i`·`risk_i` 세 질문만 Jev로 돌려 마케터 라벨과 비교합니다. 여기서 질문별 정확도와 확실도 분포가 나오면 적합 점수 단계로 넘어갑니다.
