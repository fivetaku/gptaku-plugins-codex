# 시험 계획 (제안마다 붙인다)

## 기본 절차 (R3에서 실제로 돌린 방식)

1. 업무 표본 50~100건을 모은다. 실제 자료가 없으면 실제와 비슷하게 만들고 "합성"이라고 적는다. 어려운 건(부정어, 묻는 꼴의 지시, 애매한 경계)을 2~3할 섞는다.
2. 실행 전에 정답을 붙이고 해시로 잠근다(`lock.txt`). 정답이 사람끼리 갈릴 건은 따로 표시한다.
3. id 해시로 dev 4할 / holdout 6할을 나눈다.
4. 조건을 정해 돌린다: 질문 언어(한/영), 보기 순서 뒤집기(Choice), 묶음 여부. 반복 2회.
5. dev에서 "자동 처리 중 오답 0"이 되는 가장 낮은 확실도 문턱을 고른다. holdout에서 자동 처리율과 자동 처리 중 오답을 확인한다.
6. 운영 뒤에는 사람에게 넘어간 건에 정답을 붙여 표본으로 다시 쌓고, 문턱을 주기적으로 다시 맞춘다.

R3 예: 원 실험(jev-1.13.0)은 dev에서 0.85를 골라 holdout 54/59 자동(92%)·자동 처리 중 오답 0. 재측정(jev-1.14.0)은 같은 절차로 0.70이 나와 holdout 57/59 자동(97%)·자동 처리 중 오답 0, 사람에게 넘긴 2건이 모두 실제 오답이었다. 모델이 바뀌면 문턱도 다시 고른다.

## 재는 것

- 정확도(조건별·질문별), 확실도 구간별 정확도
- 자동 처리율과 사람 넘김 건수 — 업무 효과는 이 숫자로 말한다
- 지연: HTTP 왕복만(p50/p90). 환산 비용은 쓰지 않는다
- 반복 일치, 보기 순서 뒤집기로 바뀐 건

## 바로 쓰는 템플릿

이 스킬의 `bench/` 폴더 (`$PLUGIN_ROOT/skills/golla-jev/bench/`)
- `build_items.py`: 워크플로별 질문·보기·문항·정답 정의, dev/holdout 분할, 해시 잠금
- `run.py`: 조건 4종(ko·en·ko_rev·packed) 실행. 키는 환경변수 `TYPESAFE_API_KEY`에서만 읽고 출력하지 않는다
- `analyze.py`: 채점·구간별 정확도·틀린 문항 목록
- `sweep.py`: 문턱별 자동 처리율 표

새 업무는 `bench/`를 작업 폴더로 복사한 뒤 `build_items.py`의 `WF` 사전만 바꿔 쓴다. 플러그인 안의 원본은 고치지 않는다. 실행 순서: `python3 build_items.py` → `python3 run.py`(키는 명령줄에 값을 직접 쓰지 말고 비밀 저장소에서 꺼내 `TYPESAFE_API_KEY`로 주입) → `python3 analyze.py` → `python3 sweep.py`.

## 성공 기준 정하기

- 되돌리기 쉬운 일(분류·보드·초안): holdout 자동 처리 중 오답 0~1건, 자동 처리율 80% 이상이면 시범 운영.
- 되돌리기 어려운 일(발송·결제·삭제): Jev는 "멈출지"만 판단하고 실행은 사람 확인 뒤. 오류·시간 초과는 막는 쪽.
