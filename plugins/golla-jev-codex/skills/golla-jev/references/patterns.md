## C. 같은 원리의 다른 모양

- **선택은 Jev, 생성은 코드**: 코드가 후보를 만들고 Jev가 고른다(jev-search).
- **눈 → 스위치 → 손**: 이미지 입력 앞단.
- **강한 신호가 그은 선을 확률로 다시 긋지 않는다**: 시각·주소판·갈래 순 분할(patrol-jev).
- **신호 질문 여러 개 + 코드 합산이 최종 판정 하나보다 강하다**: 피싱 단독 62.6% → 신호 5개 회귀 95.0%, 재정렬 융합 +0.090(https://github.com/fivetaku/awesome-jev-study `ko/projects/454-jev-phishing-bench.md`).
- **생성 모델 옆의 보조 두뇌**: NPC·배경음악·슬랙 펫(Jeventus)처럼 상태만 판정하고 말은 템플릿/LLM이(GC AI 해커톤).
- **기존 도구의 기본 연산으로**: grep(jgrep), SQL 함수, 린터(gallant), GitHub 라벨러(DeciLabel), 서킷 브레이커.

## D. 피지컬 AI·장비 (두 속도 루프)

공통: Jev는 픽셀을 보지 않는다. 검출기·센서·에뮬레이터가 만든 상태 JSON + 코드가 만든 "지금 가능한 동작" 메뉴만 받고, 하나를 고른다. 궤적·IK·토크·충돌 정지는 코드(수백 Hz), Jev 판단은 2~10Hz.

| 사례 | 구조 | 수치(저자 보고) |
|---|---|---|
| jev-askable-arm | ManiSkill Franka, 영어 목표 → 약 30개 기본 동작 메뉴에서 Choice. 토크·궤적은 안 냄 | 없음 |
| jev-drone | MuJoCo, 기하 제어기 약 500Hz · Jev 약 2.5Hz 전술 판단 | 2.5Hz |
| 쌍팔 로봇 | 3층 제어 중 의사결정 층만 Jev, IK·물리는 코드 | 응답 약 500ms, 시도당 약 0.5엔 |
| typesafe-mario | 화면 대신 에뮬레이터 JSON, 작게 잡은 버튼 메뉴 Choice → 몇 프레임 진행 후 다시 묻기 | 라이선스 없음(코드 재사용 금지) |
| Jev plays Doom | 구조화 글로 초당 약 10회 다음 동작 | 시간당 약 $7(벤더) |
| jev-pager(장비 감시와 같은 꼴) | 알림마다 사람 호출 여부 판정, 관측값(CPU)을 state에 넣자 정밀도 0.63→0.92 | 136건 중 오경보 1 |
